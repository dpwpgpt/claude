# BI Analyst Bot

Личный Telegram-бот — AI BI-аналитик по данным в MS SQL Server. Задаёшь
вопрос на естественном языке («Сколько заказов было в прошлом месяце?»,
«Топ-10 клиентов по сумме продаж») — бот сам находит нужные таблицы в схеме
базы данных, с помощью Claude превращает вопрос в T-SQL-запрос, выполняет
его и присылает результат таблицей (или CSV-файлом, если строк много).

## Как это работает

1. При старте бот подключается к MS SQL Server и читает схему базы данных
   через `INFORMATION_SCHEMA` (таблицы, колонки, типы, первичные ключи) —
   вручную описывать таблицы не нужно.
2. На вопрос пользователя Claude получает эту схему и генерирует один
   read-only SQL-запрос (SELECT / WITH ... SELECT).
3. Запрос проходит проверку: разрешён только один оператор SELECT, без
   INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/EXEC/BACKUP/системных процедур
   (`sp_`/`xp_`) и т.п. — если запрос не проходит проверку, он не
   выполняется.
4. Запрос выполняется с ограничением на число строк (`MAX_ROWS`), результат
   форматируется таблицей в сообщении или, если он большой, присылается
   файлом `result.csv`.

## Команды

- **Любой текст** — вопрос на естественном языке о данных.
- **/schema** — показать таблицы и колонки, которые видит бот.
- **/refresh_schema** — перечитать схему базы данных и глоссарий колонок
  заново (если в базе или в `data/column_glossary.json` что-то изменилось).

## Глоссарий колонок (синонимы на человеческом языке)

Технические имена колонок не всегда понятны пользователю («Filial»,
«BEP1», «ZalogMassa»). Чтобы Claude понимал вопросы вида «покажи схему
кредитования» или «залоговую массу по регионам», опиши колонки в
`data/column_glossary.json`:

```json
{
  "dbo.DataSet_Table_1_MainLombard": {
    "Date": "Дата",
    "Region": "Регион",
    "Filial": "Филиал, отделение",
    "Plan": "План",
    "BEP1": "SLE, ТБ1",
    "Tariff": "Схема, тариф, схема кредитования",
    "TariffType": "Группа тарифов",
    "Interest": "Сбор%, выручка",
    "ZalogMassa": "Залоговая масса"
  }
}
```

Ключ верхнего уровня — `схема.таблица`, значения — колонка → синонимы
через запятую. Эти описания подмешиваются в схему, которую видит Claude
при генерации SQL (как комментарий рядом с колонкой), но никак не влияют
на сам SQL. Путь к файлу можно поменять через `COLUMN_GLOSSARY_PATH` в
`.env`. После правки файла — `/refresh_schema` в боте, перезапуск не
нужен.

## Безопасность — прочитай перед использованием

Это инструмент для выполнения произвольных SQL-запросов, сгенерированных
LLM, к реальной базе данных. Встроенные проверки — это дополнительный
рубеж защиты, а не замена правильных прав доступа:

- **Используй отдельный SQL-логин только на чтение.** Заведи в MS SQL
  Server пользователя, у которого есть только `GRANT SELECT` на нужные
  таблицы/представления (роль `db_datareader`, без `db_datawriter` и без
  прав на DDL). Тогда даже если проверка запроса что-то пропустит, ничего
  испортить не получится.
- **Обязательно задай `ALLOWED_TELEGRAM_USER_IDS`** в `.env` — иначе бот
  будет выполнять запросы к твоей базе для любого пользователя Telegram,
  который его найдёт.
- `MSSQL_ALLOWED_SCHEMAS` позволяет ограничить, какие схемы базы данных
  (например, только `dbo`) вообще видны боту и попадают в промпт к Claude.
- `MSSQL_ALLOWED_TABLES` ограничивает бота конкретными таблицами (например,
  `dbo.DataSet_Table_1_MainLombard`) — Claude вообще не узнает о
  существовании остальных таблиц и не сможет их запросить. Это основной
  способ ограничить бота одной таблицей или небольшим набором таблиц.
  Для железной гарантии (а не только на уровне промпта) дополнительно
  выдай SQL-логину бота `GRANT SELECT` только на эти таблицы, как описано
  выше.
- `MAX_ROWS` ограничивает число строк, которые бот вернёт, но не мешает
  серверу SQL Server выполнить сам запрос по большой таблице целиком, если
  модель не добавила `TOP` — при работе с очень большими таблицами стоит
  дополнительно настроить лимиты на стороне SQL Server.

## Установка

```bash
cd agents/personal/bi-analyst-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:

- `TELEGRAM_BOT_TOKEN` — токен, полученный у [@BotFather](https://t.me/BotFather).
- `MSSQL_SERVER`, `MSSQL_PORT`, `MSSQL_DATABASE`, `MSSQL_USER`,
  `MSSQL_PASSWORD` — подключение к MS SQL Server (SQL Server должен быть
  доступен по сети с той машины, где работает бот, и иметь включённый
  TCP/IP и SQL Server Authentication).
- `ALLOWED_TELEGRAM_USER_IDS` — см. раздел «Безопасность» выше.

`ANTHROPIC_API_KEY` заполнять не обязательно: Anthropic SDK сам найдёт
учётные данные — через `ANTHROPIC_AUTH_TOKEN` или через профиль,
сохранённый командой `ant auth login`, если один из них уже настроен на
машине, где запускается бот. Ключ нужен, только если ни того ни другого
нет.

## Запуск

```bash
python main.py
```

Бот запускается в режиме polling. При старте в логах появится строка о
количестве загруженных таблиц.

## Деплой на сервер

Для продакшена — Docker-контейнер с автоперезапуском:

```bash
docker compose up -d --build
```

Подробная пошаговая инструкция для VDS (Ubuntu/Debian): [DEPLOY.md](DEPLOY.md).

## Ограничения

- Понимание вопроса и качество SQL-запроса зависят от модели Claude —
  сложные или неоднозначные вопросы иногда потребуют переформулировки.
  Включённый по умолчанию режим `SHOW_GENERATED_SQL=true` показывает
  сгенерированный запрос перед результатом, чтобы это было видно.
- Бот не поддерживает запись данных, DDL или вызов хранимых процедур — это
  инструмент только для чтения и анализа.
- Схема базы данных читается один раз при старте и кешируется в памяти;
  используй `/refresh_schema` после изменений в структуре базы.

## Структура проекта

```
bi-analyst-bot/
├── main.py                # точка входа
├── requirements.txt
├── .env.example
├── data/
│   └── column_glossary.json  # человеко-понятные названия/синонимы колонок
└── src/
    ├── config.py           # загрузка настроек из окружения
    ├── db.py                # подключение к MS SQL, чтение схемы, выполнение запросов
    ├── glossary.py           # загрузка глоссария колонок из JSON
    ├── nl2sql.py              # генерация SQL из вопроса через Claude API
    ├── sql_guard.py            # проверка, что запрос — безопасный read-only SELECT
    ├── formatting.py            # форматирование результата (таблица / CSV)
    ├── handlers.py               # обработчики команд/сообщений Telegram
    └── bot.py                     # сборка и запуск приложения
```
